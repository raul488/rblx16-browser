# AGENTS.md — RBLX2016 browser port

This repo runs the leaked 2016 Roblox C++ client in the browser through
Emscripten/WebAssembly. The goal is offline Play Solo: local `.rbxl`/`.rbxlx`
files, the real 2016 engine and Lua core GUI, no Roblox authentication or
multiplayer. Only the login menu is browser-owned; everything in-game is the
engine.

Treat `roblox-2016-source-code-master/` as read-only. All port changes live in
`port/` and `web/`.

## Quick start

```sh
# 1. Toolchain paths used by the scripts
#    Emscripten: /home/raul/emsdk
#    Python:     /home/raul/python312
#    Boost:      /home/raul/boost_1_56_0

# 2. Generate include mirror (only after header changes / first checkout)
python3 port/tools/gen_ci_includes.py

# 3. Build engine objects (incremental when objects exist)
python3 port/build/build.py --project all --jobs 2
python3 port/build/build_network.py --jobs 2
python3 port/build/build_gfx.py --jobs 2
python3 port/build/build_g3d.py --jobs 2
python3 port/build/build_bullet.py --jobs 2
python3 port/build/build_extras.py --force

# 4. Shader packs (needs the no-opt ShaderCompiler; see below)
python3 port/build/build_shaders.py

# 5. Link + preload content/shaders
python3 port/build/link.py

# 6. Serve with COOP/COEP (required for SharedArrayBuffer/pthreads)
python3 web/serve.py 8080
# open http://127.0.0.1:8080/
```

`port/build/build-wasm.sh` runs the include mirror, engine build and link in one
shot, but not the gfx/network/g3d/bullet/extras/shader steps.

Build outputs: `web/js/rblx2016.js` (~485 KB), `rblx2016.wasm` (~57 MB) and
`rblx2016.data` (~107 MB, preloaded `web/content` + `web/shaders`).

## Build system details

- All engine objects are compiled by `port/build/build.py` with `-O0` by
  default, plus `-fwasm-exceptions`, `-pthread`, `-msimd128`, `-msse2`,
  `-sUSE_SDL=2`.
- `OPTIMIZED_SOURCES` in `build.py` adds `-O2 -fno-strict-aliasing` for the load
  path (v8xml, v8tree/Instance, v8world, v8kernel, script, Lua 5.1,
  DataModel/Workspace/PartInstance, Humanoid, Network/Player) and the GUI/render
  path (Gui*, text layout, Camera, Lighting, Sky, MegaCluster, SmoothCluster).
  `build_gfx.py` optimizes everything it compiles.
- Object caching is by file existence, not by flag hash. If you change flags,
  rerun the affected build with `--force --only <path>` or the object is stale.
- `build_gfx.py` and the other gfx scripts have separate output dirs under
  `port/out/`.
- `build_shaders.py` drives a Linux-built 2016 `ShaderCompiler`
  (`SHADER_COMPILER` can point at it). The pack post-pass fixes GLSL ES 3
  dynamic matrix indexing, fragment precision and SkyVS PSIZE.
- `link.py` preloads `web/content` at `/content` and `web/shaders` at
  `/shaders`. **Edits to `web/content/**` only take effect after relinking**,
  because content is embedded in `rblx2016.data`.
- Link flags: `-pthread`, `-sPTHREAD_POOL_SIZE=8`, `-sALLOW_MEMORY_GROWTH`,
  `-sINITIAL_MEMORY=256MB`, `-sMAXIMUM_MEMORY=2GB`, `-sSTACK_SIZE=8MB`,
  `-sFETCH=1`, `-sNO_EXIT_RUNTIME=1`, `-sASSERTIONS=2`.
- Final wasm must be served with `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: require-corp`. `web/serve.py` sets both.
- Use `--only <substring>` to rebuild one or a subset of files, e.g.
  `python3 port/build/build.py --project app --only 'v8datamodel/DataModel.cpp' --force --jobs 1`.

## Runtime architecture

### Entry flow

1. `web/js/app.js` creates the Emscripten module (warmed from the login screen).
2. `rblx_start_place(data, size, username, assetBase)` initializes the engine,
   creates the DataModel **with the stock LoadingScript enabled**, starts
   RunService, creates the WebView and returns. It does not load the place.
3. The shell starts the frame loop, polls `rblx_loading_gui_ready`, waits for
   the loading GUI/textures to paint, hides the HTML splash and calls
   `rblx_load_place()`.
4. `rblx_load_place` deserializes the place in a Write task, sets up services,
   spawns the local player, positions the camera, starts core scripts and marks
   `g_placeLoaded`.
5. `rblx_frame` calls `DataModel::renderStep(dt)` under the Write lock, detects
   when the local character exists, then calls `DataModel::setIsGameLoaded(true)`.
   That fires `game.Loaded`, which fades/removes the stock loading GUI.
6. `g_view->frame()` renders outside the lock. `dt` is clamped to 0.1 s.

### Lua

- Lua 5.1.4 runs through `LuaVMDummy.cpp` with the local compiler. Bytecode is
  finalized with the DAX transform before execution. Do not switch to
  `LuaVMServer.cpp`/`LuaVMClient.cpp`; that produces bytecode this interpreter
  misreads (wild jumps, heap corruption).
- `LuaVMDummy::canCompileScripts()` is true, so core scripts are read from
  `web/content/scripts` at runtime.
- `port/src/WebClient/WebCoreScripts.cpp` reproduces the
  `StudioConfigurer::configure` bootstrap for the offline subset:
  - `RobloxGui.Modules` is built from `web/content/scripts/Modules`;
  - `RobloxReplicatedStorage` is created if missing;
  - `ServerStarterScript` and `StarterScript` are started via
    `DataModel::startCoreScripts`.
- Core GUI is the real 2016 Lua: Topbar, SettingsHub, BackpackScript, Chat,
  Playerlist, health. Do not replace it with HTML.
- `StandardOut` is connected to stderr, so Lua `print`/`warn`/errors appear in
  the browser console.

### GUI/loading/leave

- `LoadingScript.lua` is started by `DataModel::createDataModel(..., true)`.
  It builds `RobloxLoadingGui`; `rblx_loading_gui_ready` checks it.
- The HTML `#loadingBar` is only a pre-engine splash styled with the stock
  loading assets (`darkLoadingTexture.png`, `loadingCircle.png`) and is hidden
  once the engine GUI is ready.
- Leaving uses the engine Settings → Leave Game page. Its `Exit` verb is
  registered in `main.cpp` (the native implementation is in
  `WindowsClient/GameVerbs.cpp`). The shell reloads the page to get a clean
  engine, instead of reinitializing in place.
- `UseInGameTopBar=true` and `UserAllCamerasInLua=true` are forced at startup,
  matching the desktop `ClientAppSettings.json`. Without the topbar flag,
  `Chat.lua` clears the GUI inset and the topbar is off-screen; without the
  camera flag, C++ `Camera::step` overrides the Lua CameraScript.
- `UserInputService::getPlatform()` returns `PLATFORM_WINDOWS` under Emscripten;
  returning `PLATFORM_NONE` throws during Lua enum conversion and kills
  `LoadingScript`/other core scripts.

### Input

- Browser DOM button numbers map to Roblox types: `0`=left/MouseButton1,
  `2`=right/MouseButton2, `1`=middle/MouseButton3. Getting this backwards breaks
  right-drag camera and tool use.
- Right-drag requests pointer lock, drops the first locked delta, releases on
  Esc/blur, and keeps a virtual cursor position.
- Mouse movement is coalesced to one `rblx_mouse_move` per frame.
- Wheel is forwarded as `rblx_mouse_wheel` with ±1 in `position.z`.
- Blur/tab-hidden sends key-up and mouse-up for every held input so movement and
  drags cannot stick.
- The engine draws the cursor; CSS cursor is hidden while playing.
- Keyboard events use `rblx_key_event`; do not reintroduce the old JS tool-equip
  hotkey. `BackpackScript` owns Tools and HopperBins.

### Rendering / audio

- WebGL2 via the 2016 GfxCore GL backend and Emscripten GLFW context.
- The framebuffer follows the canvas/ResizeObserver; the 3D viewport is full
  screen with the topbar overlaid.
- Default R6 animations are local KeyframeSequences in
  `web/content/animations`; `KeyframeSequenceProvider` accepts local
  `rbxasset://` URLs.
- `fmod_stubs.cpp` is a WebAudio shim: FMOD calls queue commands on engine
  threads, `rblx_audio_pump` runs them on the main thread. Audio is 2D only.

### Physics

- `DataModel::renderStep` runs on the main thread; the Physics job runs on the
  scheduler thread and takes the Write lock.
- The Physics job accumulates wall time and runs up to 8 fixed 1/60 steps per
  wakeup, so scheduler jitter does not slow game time (cap avoids a spiral).
- `EThrottle` auto-throttling is disabled (`ThrottleDisabled`). It reacted to
  job-timing noise and could drop simulation to 1/16 even at 60 FPS.
- There is no render interpolation; below 60 FPS movement looks stepped.

### Content and assets

- Local `rbxasset://` content resolves to `/content/...` before URL
  reconstruction; local files win over HTTP.
- `rbxassetid://N` and raw `roblox.com/asset/` URLs are rewritten to
  `<origin>/asset/?id=N` and kept on the local proxy (skip
  `reconstructAssetUrl`, which would send them back to roblox.com).
- `web/serve.py` proxies `/asset/?id=N` to
  `https://assetdelivery.roblox.com/v1/asset?id=N`, follows redirects, and
  caches bytes in `web/asset-cache/`.
- Since 2024 assetdelivery requires a session for most assets. The server reads
  `ROBLOSECURITY` (env) or `asset-cookie.txt`/`asset-cookie` next to `web/`
  (never inside `web/`), and optional `ASSET_PLACE_ID`.
  `ASSET_DELIVERY_BASE` overrides the upstream URL for tests.
- The login page has an Asset delivery cookie field (password input, masked),
  Save/Remove. It uses `GET/POST/DELETE /cookie`, requires header
  `X-RBX-Cookie: 1`, writes the file with mode 0600, and never returns the
  value. The cookie UI is a convenience; env/file works without it.

### HttpService

- `HttpService` is patched: constructor defaults `HttpEnabled=true` under
  Emscripten, the property is script-visible, and the per-place gate is skipped.
  `main.cpp` also enables it on any serialized HttpService after load.
- `GetAsync`, `PostAsync`, `JSONEncode`, `JSONDecode`, `UrlEncode`,
  `GenerateGUID` work.
- Content HTTP uses synchronous `emscripten_fetch` on worker threads only.
  HttpService async calls run the same fetch on a detached boost thread and
  resume the Lua yield there. Never call synchronous HTTP from the browser main
  thread.
- Cross-origin requests are subject to browser CORS. Roblox asset downloads go
  through the same-origin `/asset` proxy instead.

## Debugging and testing

- Serve from `python3 web/serve.py 8080`; tests in this repo historically used
  port `8781` as well. Only one server per port.
- Headless Chromium runs SwiftShader and can be ~1 FPS on this machine. Do not
  use FPS or load timing from headless as a benchmark; use state checks,
  screenshots and engine logs.
- Playwright lives at
  `/tmp/opencode/rblx2016-wasm-spike/node_modules/playwright`.
  Launch with `--enable-unsafe-swiftshader --use-gl=swiftshader --no-sandbox
  --disable-dev-shm-usage`.
- Engine logs (StandardOut and `RBLX2016:` lines) go to the browser console.
  `print`, `warn` and Lua errors are visible.
- `window.__rblxMod` is intentionally not exposed. For tests, temporarily add
  `window.__rblxMod = mod;` in `installInput` (or inside the `has_view` branch)
  and remove it afterwards.
- Debug exports: `rblx_debug_player` (position/health/backpack/character),
  `rblx_debug_gui` (CoreGui and PlayerGui rects/visible/active),
  `rblx_debug_joints`, `rblx_debug_anim`, `rblx_debug_asset`,
  `rblx_run_script` (injects a LocalScript into PlayerScripts).
- Useful smoke checks:
  - Doomspire loads, topbar visible, hotbar shows Sword/Rocket/etc.
  - Press `1` or click a hotbar slot: tool leaves Backpack (child count drops)
    and appears under Character.
  - Engine Settings menu opens with the hamburger at the top-left, tabs work,
    Resume closes, Leave returns to the login (page reload).
  - Trains V2.0 (2008): HopperBins appear in the hotbar, clicking one sets
    `Active=true`; clicking again deactivates.
  - Right-drag rotates the camera; wheel zooms; WASD moves; blur stops movement.
  - Loading shows the stock `LoadingScript` screen, then fades when the avatar
    exists.
- Known place-script errors are expected: `game.Selection`,
  `ColorSequenceKeypoint`, `GetDescendants`, `Activated`,
  `FindFirstAncestorWhichIsA`, `HttpService` module IDs that need auth. Do not
  confuse these with core GUI failures.
- Restarting a play session reloads the page. A dropped local file must be
  dropped again after leaving.

## Important engine/port facts

- DataModel is `VISIT_SOLO`: `backendProcessing` and `frontendProcessing` are
  both true because there is no `Client`/`Server` service.
- `Players::serverIsPresent` is false, so TweenService uses `RenderStepped`
  stepping and works.
- `LoadingScript` waits for `game.Loaded`; `setIsGameLoaded` is fired after the
  local character exists (8 s fallback) from `rblx_frame`.
- `ReplicatedFirst` auto-fires its finished-replicating signal from
  `gameLoadedSignal` in Play Solo.
- Local player scripts (ControlScript/CameraScript/character sounds/Animate)
  load from `web/content/fonts/*.rbxm*` (legacy paths).
- `ContentProvider` reads files fully into memory before XML parsing; seeking
  the VFS stream falls back to one-byte reads and is very slow.
- `rbx2016.data` is large because all of `web/content` and `web/shaders` are
  preloaded. Keep it that way; runtime HTTP for UI assets is not implemented.
- The `-O2` flags use `-fno-strict-aliasing`; keep that for legacy engine code.
- If you add a new engine source patch, mirror its relative path under
  `port/src_patch/` and rebuild that file; `build.py` prefers the patch file.
- Patched headers go through `port/shim/patched` + `gen_ci_includes.py`; do not
  edit `port/shim/include` or `port/shim/caseinclude` (generated, absolute
  symlinks).

## Agent conventions

- Never edit `roblox-2016-source-code-master/`. Use `port/src_patch/` or the
  WebClient/platform/shim layers.
- Keep engine behaviour authentic where possible; fix the port/launcher, not
  the stock scripts, unless the script is place content under test.
- Reuse existing services and engine paths (core Lua GUI, BackpackScript,
  LoadingScript, assetdelivery proxy) instead of adding parallel JS
  implementations.
- Smallest complete change: include callers, tests/fixtures and docs
  (`port/STATUS.md`, this file) in the same change.
- Do not add new runtime dependencies without a concrete need.
- Do not commit secrets. `.ROBLOSECURITY` values are full account sessions.
- Do not commit generated output, caches or the engine source; see `.gitignore`.
- Verify at least: page loads, topbar/menu, one tool or HopperBin, and no new
  `PAGEERR`/Lua core-GUI errors. Report headless timing caveats explicitly.
- When changing `web/content/**`, relink before testing (content is embedded).
- When changing link flags or preloaded paths, expect a full relink and a
  noticeably different `rblx2016.data`/wasm size.
- Keep `port/STATUS.md` current: it is the human-readable source of truth for
  features, fixes, build state and known gaps.

## Known gaps

- No networking or multiplayer; Players/Player are local.
- Remote content is assetdelivery only; no general HTTP for UI assets.
- Assets requiring auth need the server-side cookie; some main-thread sync
  module loads still fail.
- No positional audio, no full material/lighting fidelity, no skybox.
- No physics interpolation; sub-60 FPS looks stepped.
- Software WebGL (SwiftShader) is CPU-bound; headless performance is not
  representative.
- Restart via page reload; dropped local files are not preserved.
- Old places may use APIs removed in 2016 (`game.Selection`) or newer Lua
  constructors (`ColorSequenceKeypoint`); only their own scripts fail.
